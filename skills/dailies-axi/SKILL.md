# Dailies AXI

Run `dailies-axi --help` for commands and `dailies-axi doctor` for prerequisites. Work in the private project directory. Keep originals, proxies, transcripts, frame grabs, reviews and feedback off Git and out of uploads. Never share or export a footage review through Lavish, including through its browser menu.

1. For a new footage review, run `dailies-axi open <video> [workspace-dir]`. It creates a private `<video-name>-review/` workspace in the current directory, ingests as `cut`, detects shot cuts, transcribes with local Whisper when available, builds `v1`, and opens it in Lavish. Ask once for the audience, platform, format, target length, goal, and reviewer roles. For learning, pass the structured fields with `--brief-file FILE`. Use `--brief TEXT` or the interactive prompt for the free-text brief. Check `transcript.status` in the receipt. Pass `--language CODE` for non-Mandarin speech or `--srt FILE` for existing subtitles. Read `session.url` as soon as it prints and keep the command attached to collect feedback. Use `--no-poll` to hand off the link and wait separately with `dailies-axi poll <review_file>` using the printed path. Use `--asset ID` or `--version vN` to change the defaults. To continue in an existing footage workspace, open its working composition as described below.
2. For a HyperFrames edit, run `dailies-axi open <composition.html>`. It copies a standalone file into a private workspace as `source/index.html` or uses the existing workspace when given its working file. Give each segment a unique HTML ID and set `data-review-clip` to its asset ID. Set `src` to the local original or use a proxy path `media/<asset-id>.mp4` with `data-review-source` pointing to the original. Paths to originals are relative to the input HTML or absolute. The command ingests missing assets at the composition rate and reuses those already ingested. Author cuts with integer `data-start-frame`, `data-duration-frame`, and `data-media-start-frame` for start, length, and proxy offset. Frame-aligned seconds attributes still work. If both forms are present, they must agree. Check the build receipt for exact frame bounds and `edl.json` for the source mapping. Use `dailies-axi transcribe <asset-id> --srt FILE` to import corrected source-time subtitles when needed. For the bundled animation, run `dailies-axi init --sample` and then `dailies-axi open source/index.html`.
3. Click the timeline or a transcript line to jump to a frame and clear any range. Drag on the timeline to select a range with shot-cut snapping. Shift-click transcript lines to select or extend from the original line. Playback and frame steps keep the range while the playhead and transcript highlight follow the current frame. Use Shift+Left/Right to adjust the end, or click the range chip or press Esc to clear it. Burned-in captions appear in the video. **Transcript overlay** starts off and displays a labelled transcript in the preview only. Ask the reviewer to mark areas or ranges and choose **Send feedback to agent**. The Dailies poll records the submitted video batch in the version’s `notes.json` and preserves the Lavish receipt. If the reviewer chose **Send & End**, read the final feedback once and stop polling that session.
4. Follow the poll receipt's `feedback.next_step`. Use `dailies-edit` and `dailies-cut plan vN` for footage changes. Use the locked note's exact `media_frame` with `dailies-axi frame` for an independent frame grab. Ranges are half-open.
5. After the previous batch locks, send the verified candidate with `dailies-axi open source/index.html --note "Change summary" --outcomes CANDIDATE/changes.json` from the workspace. The next review shows clickable frames or ranges in the previous-round list and posts its link in the previous Lavish session. Use explicit `build`, `review` and `poll` for a custom output directory. For an independently authored composition without managed footage, the legacy map of note IDs to strings or `{note, frame, end_frame?}` still works. Frame targets are zero-based on the new version, and `end_frame` is exclusive.

## Reviewer identity and reactions

On the first open, pass `--brief-file FILE` to capture the project ID, platform, format, stable reviewer IDs and optional decision owner. Use role labels and keep the brief in the private workspace. If there is exactly one reviewer, the review page uses that ID. With multiple reviewers, the sender can select an identity or send anonymously.

The previous-round list shows the delivered outcome, frame links, and any preference disclosure. The reviewer can accept, reject, choose an alternative, or reopen it with a new note. Send reactions alone or together with notes. Poll locks notes schema 3 with `reviewer`, `reactions` and optional note-level `reopens`. Existing schema 2 batches stay readable. Hand the locked batch to the dailies-edit skill for classification and learning.
